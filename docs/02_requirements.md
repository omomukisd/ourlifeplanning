# 02. 要件定義書（v0.4）

> **このリポジトリは公開されています。** 実際の金額・年齢などは書かない。
> 例が必要な場合は、明らかに架空の値（サンプル世帯）を使う。

優先度：**Must** = MVPに必須 / **Should+** = MVP後に最優先 / **Should** = MVP後すぐ / **Could** = 余裕があれば

## 1. 機能要件

### 1.1 世帯・人物
| ID | 要件 | 優先度 |
|----|------|--------|
| F-01 | 世帯メンバー（大人・子ども）を登録できる。項目は生年月日（または生年）、役割 | Must |
| F-02 | 子どもごとに進学コースを設定できる。段階（保育〜大学院・専門学校・6年制学部など）と公立／私立を選び、段階は**後から追加できる**マスタデータで持つ | Must |

### 1.2 収入
| ID | 要件 | 優先度 |
|----|------|--------|
| F-10 | 大人ごとに**手取り年収**（ボーナス込み）を入力できる | Must |
| F-18 | 大人ごとに**額面年収**を入力できる（年金の自動推計に使う。手取りの計算には使わない） | Must |
| F-17 | 額面年収を入力し、手取りを簡易計算する（税・社会保険の簡易モデル） | Should |
| F-11 | 退職年齢と**収入カーブ**（年齢の区間ごとの昇給率。例：〜50歳 +1.5%/年、〜60歳 0%、60歳以降は再雇用で60%）を人ごとに設定できる | Must |
| F-12 | 育休・時短など、一時的に収入が減る期間を設定できる | Should |
| F-13 | 公的年金を**自動で推計**する：ねんきん定期便の加入実績額 ＋ 今後の加入期間の分（退職年齢・額面年収から計算）。受給開始年齢を変えられる | Must |
| F-14 | 退職金を入力できる（不明なら0） | Should |
| F-15 | 児童手当を自動で加算する | Should |
| F-16 | サイドFIRE期間の収入（例：月◯万円を◯歳まで）を設定できる | Must |
| F-19 | 会社を辞めた後に自分で払う**国民年金保険料（60歳まで）と国民健康保険料**を自動で支出に加える（簡易計算） | Must |

### 1.3 支出
| ID | 要件 | 優先度 |
|----|------|--------|
| F-20 | **基本生活費**（月額）を入力できる。趣味予算は含まない | Must |
| F-21 | **趣味予算**（月額）を基本生活費と分けて入力できる | Must |
| F-22 | 教育費を進学コースから自動計算する（標準的な金額表を内蔵し、編集できる） | Must |
| F-23 | 住居費：住宅ローン以外の固定資産税・修繕費を入力できる | Must |
| F-24 | 車の買い替えなど、単発・周期的な支出をイベントとして登録できる | Must |
| F-26 | F-23・F-24の**プリセット**を選ぶだけで登録できる（例：車の買い替え、家電の買い替え、管理費・修繕積立金、固定資産税）。金額・周期・値上がり率は編集できる | Must |
| F-25 | 退職後の生活費を、現役時の◯%のように変えられる | Should |

### 1.4 ローン
| ID | 要件 | 優先度 |
|----|------|--------|
| F-30 | 残高、残り期間、返済方式（元利均等）を入力し、毎年の返済額・残高を計算する | Must |
| F-35 | **ペアローン**：ローンを複数持て、それぞれに名義人を設定できる（金利・期間・控除は別々に計算） | Must |
| F-31 | **変動金利に対応**：金利の変更（いつから何%）を入力でき、将来の金利をシナリオで変えられる | Must |
| F-32 | 住宅ローン控除を名義人ごとに反映する。**控除が終わると手取りが減る**ことを表現する（§03 3.2） | Must |
| F-33 | 繰上げ返済をイベントとして登録し、効果を比較できる | Should+ |
| F-34 | 住宅ローン以外のローン（車・奨学金など）も同じ仕組みで登録できる | Could |

### 1.5 資産
| ID | 要件 | 優先度 |
|----|------|--------|
| F-40 | 資産を口座の種類ごとに管理する。種類は**後から追加できる**マスタデータで持つ（現預金、NISA、企業型DC、iDeCo、課税口座、財形、貯蓄型保険、その他など） | Must |
| F-41 | 種類ごとに**毎月の積立額**と**想定利回り**を設定できる | Must |
| F-42 | **企業型DC・iDeCoは原則60歳まで引き出せない資産**として区別し、FIRE計算では引き出し可能時期を考慮する | Must |
| F-43 | 資金が足りない年は、現預金 → 課税口座 → NISA の順に取り崩す（順序は変更可） | Should |

### 1.6 シミュレーション・前提値
| ID | 要件 | 優先度 |
|----|------|--------|
| F-50 | 現在から最年長の大人が100歳になるまで、**年単位**で収支・資産残高を計算する | Must |
| F-51 | 前提値（インフレ率、利回り、昇給率、ローン金利など）を画面で確認・変更できる | Must |
| F-52 | **標準／悲観**のシナリオを持ち、前提値の組み合わせを切り替えて比較できる | Must |
| F-53 | 楽観シナリオ、利用者が作るシナリオ | Should |
| F-54 | 運用利回りのばらつきを考慮した確率的な試算（モンテカルロ法） | Could |

### 1.7 3つの問いへの回答（ダッシュボード）
| ID | 要件 | 優先度 |
|----|------|--------|
| F-60 | **Q1 老後**：資産が尽きる年齢（尽きない場合は100歳時点の残高）を表示する | Must |
| F-61 | **Q2 趣味予算**：**100歳時点の資産が0円以上**となる条件で（条件は変更可）、**毎月使える趣味予算の上限**を逆算して表示する | Must |
| F-62 | **Q3 FIRE**：完全FIRE／サイドFIREそれぞれの最短可能年齢と、その時点で必要な資産額を表示する。**大人ごとに退職年齢を別々に**設定でき、組み合わせごとの可否を表で表示する | Must |
| F-63 | 資産推移グラフ（種類別の積み上げ）と、年ごとのキャッシュフロー表を表示する | Must |
| F-64 | 資産がマイナス、または目標を下回る年に警告を出す | Must |

### 1.8 定期更新（実績）
| ID | 要件 | 優先度 |
|----|------|--------|
| F-70 | 月1回、資産の種類ごとの残高と、**その月の手取り額**（給与振込額。ボーナス月はボーナス込み）を入力できる | Must |
| F-71 | 計画値と実績値の資産推移を重ねて表示する | Should |
| F-72 | 手取り・現預金の増減・積立額から、**実際の支出を逆算**して表示する（12か月移動平均も表示） | Must |
| F-73 | 家計簿アプリのCSV取り込み | Could |

## 2. 非機能要件
| ID | 要件 |
|----|------|
| N-01 | **個人データはリポジトリに含めない。** 公開されるコード・ビルド成果物に実データが混ざらない構成にする |
| N-02 | 個人データは、世帯の利用者だけがアクセスできる場所に保存する（認証が必要） |
| N-03 | スマホで快適に使える（縦画面で主要な画面が完結する） |
| N-04 | 世帯の複数の利用者が同じデータを閲覧・編集できる |
| N-05 | データをファイルに書き出し・読み込みできる（バックアップ・移行用） |
| N-06 | 運用コストは無料〜月数百円程度 |
| N-07 | 計算ロジックは画面から独立させ、自動テストで検証できる |
